# rcompass 결과 보고

이 저장소의 연구 기록은 로컬 웹앱 연구 나침반(rcompass)에 있습니다. 연구자는 앱에서 "Claude Code 인계" 문서를 만들어
세션 첫 메시지로 붙여넣고, 실험이 끝나면 당신이 출력한 결과 블록을 앱에 붙여넣어 확인한 뒤 기록합니다.
앱은 당신이 쓴 값을 그대로 저장하지 않고, 연구자가 미리보기에서 확인해야 저장합니다.

## 인계 문서를 받았을 때

- "시도한 접근"에서 **기각**이나 **채택 후 철회**로 적힌 방식은, 그 이유가 해소되었다는 근거가 없으면 다시 제안하지 마세요.
  다시 제안해야 한다면 이유가 왜 해소되었는지 먼저 말하세요.
- "현재 기준선"과 그 수치를 비교 기준으로 삼으세요. 목표 달성 여부는 앱의 판정이 기준입니다.
- 코드와 Git은 연구자가 요청하지 않으면 바꾸지 마세요. 커밋, 브랜치 변경, 원본 데이터 수정은 먼저 묻습니다.
- "다음 행동"이 있으면 그것부터 확인하세요.

## 실험을 마쳤을 때

결과를 아래 형식의 블록 **하나**로 출력하세요. 인계 문서 끝의 "결과 보고 형식"에 이 실험에 맞게 채워진 틀이 있으면 그 틀을 쓰세요.

```rcompass-result
experiment: E3
dataset: DS1@v1.0
code: 3f2a9e1c
config: configs/summarize.yaml
runs:
  - {label: seed=1, metrics: {avg_latency_s: 1.82}}
  - {label: seed=2, metrics: {avg_latency_s: 1.91}}
  - {label: seed=3, metrics: {avg_latency_s: 1.77}}
files: [outputs/latency_E3.png]
note: 요약 단계를 넣어도 평균 응답 시간은 2초 안쪽이다
```

규칙
- `experiment`: 앱에서 만든 실험 ID(E 번호). 모르면 연구자에게 물어보세요. 지어내지 마세요.
- `dataset`: 앱에 등록된 데이터 버전(`DS1@v1.0`처럼). 모르면 비워 두세요.
- `code`: 실험에 쓴 커밋 SHA. 커밋하지 않은 변경으로 돌렸다면 그 사실을 `note`에 적으세요.
- `runs`: 실행(시드, 반복)마다 한 줄. `label`은 실행을 구별하는 이름(예: `seed=1`)이고, 같은 이름을 두 번 쓰지 마세요.
  `metrics`의 이름은 인계 문서의 성공 기준 지표 이름(백틱 안의 영문)을 그대로 쓰세요. 값은 숫자만 적고, 재지 않은 지표는 빼거나 비워 두세요.
- 실제로 실행해서 얻은 값만 적으세요. 추정하거나 일부 실행만 골라 적지 마세요. 실패한 실행이 있으면 `note`에 적으세요.
- `files`: 만든 그래프·표 파일 경로. 앱은 경로를 첨부 제안으로만 보여주고, 연구자가 직접 올립니다.
- `note`: 한 줄 해석. 판정(채택·기각)은 연구자가 앱에서 합니다. "채택해야 한다"고 단정하지 말고 근거만 적으세요.
